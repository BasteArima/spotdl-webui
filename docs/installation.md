## Что внутри образа

Самодостаточный образ на `python:3.12-slim-bookworm`: spotdl, ffmpeg, Deno (без него YouTube
отдаёт не всё), librespot/Zotify и само приложение. Ничего не доустанавливается при старте.

## Готовый образ или свой

**Готовый:** `ghcr.io/bastearima/spotdl-webui:latest` — публичный, собирается из ветки `main`
этого репозитория.

**Свой (форк):** workflow [`.github/workflows/build.yml`](../.github/workflows/build.yml) собирает
и публикует образ в GitHub Container Registry при каждом push в `main`/`master`. Секреты не
нужны — используется встроенный `GITHUB_TOKEN`.

1. Сделайте push в свой репозиторий и дождитесь зелёного прогона в **Actions**.
2. Образ появится во вкладке **Packages** как `ghcr.io/<owner>/<repo>` (в нижнем регистре).
3. По умолчанию пакет приватный. Проще сделать публичным — секретов в образе нет:
   **Packages → пакет → Package settings → Change visibility → Public**.
   Либо оставьте приватным и добавьте в Portainer реестр `ghcr.io`
   (**Registries → Add registry → Custom**): логин — GitHub-логин, пароль — Personal Access
   Token со scope `read:packages`.

## Стек в Portainer

**Stacks → Add stack → Web editor**, вставьте [`docker-compose.yml`](../docker-compose.yml) и
поправьте под себя:

- `image` — готовый образ или свой;
- `volumes` — пути к данным и музыке на хосте (см. ниже);
- `PUID`/`PGID` — как у Navidrome.

**Deploy the stack** → UI на `http://<сервер>:4535`. При первом открытии сервис попросит
придумать пароль (или задайте `APP_PASSWORD` заранее — см. [настройки](configuration.md#вход-и-пароль)).

Вместо вставки можно подключить стек к репозиторию (**Add stack → Repository**) — тогда
Portainer сам подтягивает изменения compose.

## Тома, порт и права

| Контейнер | Что там |
|-----------|---------|
| `/conf` | данные сервиса: `playlists.txt`, `*.spotdl`, `errors/`, cookies, креды, настройки — [список файлов](configuration.md#файлы-в-conf) |
| `/music` | библиотека: треки в `spotify/…`, m3u-плейлисты в `playlists/` |

**Порт** — `4535 → 8000` в примере; внешний выбирайте свободный (4533 обычно у Navidrome).

**Права.** Сервис стартует от root, готовит окружение и дальше работает под `PUID:PGID`
с `umask 002`, поэтому новые файлы читаемы группой Navidrome. Сам он меняет владельца только
у своих служебных папок — общую музыку не трогает. Если папки библиотеки создавались
раньше от root (например, старым автосинком), дайте группе запись один раз на хосте:

```sh
chown -R 998:100 /путь/к/музыке/spotify /путь/к/музыке/playlists
chmod -R g+rwX   /путь/к/музыке/spotify /путь/к/музыке/playlists
```

Лимиты `mem_limit`/`cpus` в compose — потолок для всего контейнера: внутри живут не только веб,
но и spotdl, ffmpeg, Deno и librespot. 1 ГБ хватает на синк большого плейлиста. Если контейнер
перезапускается посреди синка — проверьте `docker inspect spotdl-webui --format '{{.State.OOMKilled}}'`
и поднимите лимит.

## Обновление

1. Новый образ собирается после push в `main` (у готового образа — после коммита в этот репозиторий).
2. В Portainer: **Stacks → стек → Update the stack** с включённым **Re-pull image**.

Настройки, пароль, креды и прогресс апгрейда лежат в `/conf` и переживают пересоздание контейнера.

**Полный автомат (необязательно):** создайте у стека webhook (**Stack → Webhooks**) и добавьте
его URL в Secrets репозитория как `PORTAINER_WEBHOOK` — workflow сам передеплоит стек после
сборки.

## Переезд со старого контейнера автосинка

Если раньше плейлисты синкал отдельный контейнер со spotdl по расписанию, он больше не нужен:
этот сервис делает то же самое сам (автосинк во вкладке «Настройки»), с теми же путями,
шаблоном имён и форматом.

1. Поднимите этот стек на тех же томах `/conf` и `/music`.
2. Убедитесь, что UI открывается, а «Синхронизировать всё» отрабатывает (строка статуса
   вверху, вкладка «Активность», `docker logs spotdl-webui`).
3. Удалите старый стек автосинка.

Надолго оставлять оба не стоит — будет двойная работа. Одновременный синк одного плейлиста
не сломает файлы (сервис ставит файловый лок), но старый контейнер локов не ставит.

## Локальная сборка

```sh
docker build -t spotdl-webui:local .
docker run --rm -p 4535:8000 -e APP_PASSWORD=dev \
  -v /путь/conf:/conf -v /путь/music:/music spotdl-webui:local
```

## Проверка после деплоя

1. **Старт:** `docker logs spotdl-webui` — строка `[entrypoint] запуск под 998:100 …`, затем
   uvicorn; никаких установок пакетов при старте.
2. **Инструменты в контейнере:**
   ```sh
   docker exec spotdl-webui spotdl --version
   docker exec -u 998 spotdl-webui deno --version
   docker exec spotdl-webui ffmpeg -version
   ```
3. **Баннер** вверху UI пуст — или подсказывает, чего не хватает (cookies, права на запись,
   Deno, вход для Liked Songs).
4. **Плейлист:** добавьте тестовый → Sync → в `/music/spotify/…` появились треки, в
   `/music/playlists/<имя>.m3u8` — плейлист. Имена с `:` и кириллицей не ломаются
   (`NieR: Automata OST` → `NieR Automata OST.m3u8`).
5. **Добивание:** на вкладке «Ненайденные» скачайте трек по ссылке — файл появился в
   библиотеке, трек дописан в m3u и пропал из списка.
6. **Права:** `ls -ln /путь/к/музыке/spotify/…` — владелец `998:100`, файлы читаемы группой.
7. **Navidrome:** если подключён — после загрузки в карточке «Navidrome» виден последний скан,
   трек появился в плейлисте.
