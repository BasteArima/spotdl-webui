# spotdl web-ui — управление музыкой для Navidrome

Самостоятельный веб-сервис в Docker, дающий браузерный интерфейс для управления
локальной музыкальной библиотекой, которую скачивает **spotdl** из Spotify, и —
главное — для **ручного добивания треков, которые автопоиск не нашёл на YouTube**,
с автоматическим добавлением их в нужный m3u-плейлист (его подхватывает Navidrome).

Сервис мирно сосуществует с уже работающим контейнером автосинка на spotdl: делит
те же тома `/conf` и `/music`, использует **те же шаблоны путей, формат и правило
очистки имён**, и ставит файловый лок, чтобы не синхронизировать один плейлист
одновременно с автосинком.

---

## Возможности

- **Ненайденные треки** (главная фича): читает все `errors/*.txt`, группирует по
  плейлисту, показывает `Artist - Title`, тип ошибки и ссылку на Spotify. Для
  каждого трека — поле для YouTube/YT-Music-ссылки и кнопка «Найти и добить».
  Есть быстрая ссылка «искать на YT» (открывает `music.youtube.com/search`).
- **Добивание трека**: по нажатию сервис качает аудио с указанного YouTube-URL
  (метаданные берутся со Spotify), пересинхронизирует плейлист, чтобы трек попал
  в `<safe>.m3u8`, и убирает трек из errors-файла.
- **Deezer-фолбэк** (для треков, которых нет на YouTube): кнопка «Deezer» у строки
  ищет ту же запись в каталоге Deezer **по ISRC** (точное совпадение со Spotify),
  скачивает и кладёт в библиотеку с метаданными/обложкой со Spotify. Каталог
  Deezer почти совпадает со Spotify, поэтому находит то, чего нет на YouTube.
  Требует Deezer **ARL-токен** (см. раздел «Deezer»). Бесплатный аккаунт даёт
  MP3 128 kbps, Premium/HiFi — выше/FLAC.
- **Zotify (реальное аудио со Spotify, 320k)**: кнопка «Zotify 320k» у строки
  скачивает трек **прямо со Spotify** через твой аккаунт (librespot). С Premium —
  320 kbps Ogg (макс. качество Spotify), кладётся в библиотеку как обычно. Лучший
  фолбэк для треков, которых нет на YouTube, и основа будущего апгрейда качества.
  Требует креды Spotify (см. раздел «Zotify»). **Риск:** нарушает ToS, аккаунт
  может быть забанен — используется на свой риск.
- **Заливка локального файла** (для треков, которых нет на YouTube): кнопка
  «📁 Файл» у строки — выбираешь скачанный сторонним способом аудиофайл, сервис
  конвертирует его в формат библиотеки (ffmpeg), вшивает метаданные и обложку
  **со Spotify** и кладёт по тому же пути, что и обычная загрузка. Дальше — как
  всегда: sync плейлиста → трек в `<safe>.m3u8` → убран из errors. (Это ровно то,
  что spotdl делает после скачивания с YouTube, только источник аудио локальный.)
- **Управление плейлистами**: просмотр/добавление/редактирование/удаление записей
  в `playlists.txt` (формат `Имя|ссылка`), кнопки «Синхронизировать этот плейлист»
  и «Синхронизировать всё».
- **Массовое скачивание** — кнопка «Скачать все» с выбором источника (dropdown):
  из поля URL / Deezer / Spotify 320k. Применяет выбранный источник ко всем
  строкам (плейлиста или всего списка).
- **Лёгкое обновление m3u** — одиночное скачивание (Spotify/Deezer/файл) дописывает
  трек в `<safe>.m3u8` напрямую, без полного `sync` плейлиста (мгновенно, без
  нагрузки на Spotify API). Полный sync — только при «Синхронизировать всё».
- **Апгрейд качества до 320k** (вкладка «Апгрейд 320k») — фоновый процесс, который
  постепенно заменяет треки библиотеки (YouTube/Deezer) на 320k со Spotify. Идёт
  медленно (безопасный режим, паузы), **переживает рестарт** и **не качает повторно**
  уже улучшенные (персистентная метка `/conf/.webui-upgraded.json`). Старт/стоп и
  прогресс (готово/всего, ETA) — в UI.
- **Две дорожки очереди:** ручные загрузки (интерактивная дорожка) идут сразу и
  **не ждут** тяжёлый фоновый автосинк (фоновая дорожка). Один и тот же плейлист
  защищён файловым локом, поэтому дорожки не конфликтуют.
- **Панель задач** (справа снизу): статусы (в очереди с номером позиции /
  качается / готово / ошибка / отменено), **отмена** задач, лог по клику. Полные
  логи дублируются в `docker logs`.
- **Баннер окружения:** UI предупреждает, если нет `cookies.txt`, не записываема
  папка музыки или не найден Deno — до того, как что-то упадёт.
- **Валидация ссылки-источника** перед отправкой (Spotify-URL в поле YouTube не
  пройдёт). Счётчик ненайденных треков. Адаптивная вёрстка, тёмная тема.
- Простая аутентификация по токену.

## Архитектура и поведение

- Бэкенд — FastAPI (`app/`), spotdl запускается как подпроцесс с захватом
  stdout/stderr в лог задачи.
- Все тяжёлые операции идут через **один воркер-поток** → внутри сервиса нет
  параллельных загрузок. Для координации с фоновым автосинком — файловый лок
  на плейлист (`/conf/.webui-locks/<id>.lock`, best-effort).
- Имена, пути, id вычисляются **идентично** bash/sed автосинка (покрыто тестами
  `tests/test_naming.py`, включая сверку с эталонным sed):
  - safe-имя: `trim_right → заменить / \ : * ? " < > | на пробел → схлопнуть
    пробелы → trim_right`. Пример: `NieR: Automata OST` → `NieR Automata OST`.
    Кириллица/японский сохраняются.
  - id плейлиста: `md5(url)[:12]` → `/conf/<id>.spotdl`.
- Команды spotdl (те же флаги, что у автосинка):
  ```
  sync <URL> --save-file /conf/<id>.spotdl --cookie-file /conf/cookies.txt \
       --save-errors /conf/errors/<safe>.txt \
       --output "/music/spotify/{album-artist}/{album}/{track-number} - {title}.{output-ext}" \
       --m3u /music/playlists/<safe>.m3u8 --format mp3
  download "<youtube>|<spotify>" --cookie-file /conf/cookies.txt \
       --output "<тот же шаблон>" --format mp3
  ```

## Сборка и доставка через GitHub (CI/CD)

Образ **самодостаточный** (ffmpeg + spotdl + Deno + приложение в одном
`Dockerfile`) и собирается автоматически в **GitHub Actions**, публикуясь в
**GitHub Container Registry (GHCR)**. Рабочий цикл:

```
git push  →  Actions собирает образ  →  ghcr.io/<owner>/spotdl-webui:latest
          →  в Portainer жмёшь Recreate (с Re-pull)  →  подтянулся свежий образ
```

Никакого копирования файлов на сервер и ручной сборки.

### Шаг 1. Завести репозиторий и включить CI

1. Залей этот проект в репозиторий GitHub (`git push`).
2. Workflow [`.github/workflows/build.yml`](.github/workflows/build.yml) уже в
   репо — он собирает и пушит образ при каждом push в `main`/`master`. Никаких
   секретов настраивать не нужно: используется встроенный `GITHUB_TOKEN`.
3. После первого успешного прогона образ появится во вкладке **Packages**
   репозитория как `ghcr.io/<owner>/<repo>` (имя в нижнем регистре).

### Шаг 2. Сделать пакет доступным для Portainer

По умолчанию пакет GHCR **приватный**. Проще всего сделать его **публичным**
(в образе нет секретов — токен и cookies подаются в рантайме):
GitHub → репозиторий → **Packages** → выбрать пакет → **Package settings** →
**Change visibility → Public**.

> Если хочешь оставить приватным — в Portainer добавь реестр `ghcr.io`
> (**Registries → Add registry → Custom**) с логином = GitHub-логин и паролем =
> Personal Access Token со scope `read:packages`.

### Шаг 3. Поднять стек в Portainer

1. Portainer → **Stacks → Add stack** → имя `spotdl-webui` → **Web editor**.
2. Вставь содержимое `docker-compose.yml` и **замени**:
   - `ghcr.io/<owner>/spotdl-webui:latest` → свой путь (точный — в логе Actions
     или на странице Packages; всё в нижнем регистре);
   - `APP_AUTH_TOKEN=ЗАМЕНИ_МЕНЯ` → свой токен (длинная случайная строка).
3. **Deploy the stack.** UI откроется на `http://<сервер>:4535`.

> Можно вместо вставки подключить стек к Git-репозиторию (**Add stack →
> Repository**) — тогда Portainer сам тянет и `docker-compose.yml`, и
> обновления.

### Обновление после нового коммита

1. Закоммить и запушь изменения → дождись зелёного прогона Actions.
2. В Portainer: **Stacks → spotdl-webui → Recreate**, включи галочку
   **«Re-pull image»** (или **Pull latest image**) → Update.

> **Полный автомат (необязательно):** создай у стека webhook
> (**Stack → Webhooks**), добавь его URL в Secrets репозитория как
> `PORTAINER_WEBHOOK` — и workflow сам дёрнет передеплой после сборки. Тогда
> хватит одного `git push`.

### Локальная сборка (по желанию)

```sh
docker build -t spotdl-webui:local .
docker run --rm -p 4535:8000 -e APP_AUTH_TOKEN=dev \
  -v /path/conf:/conf -v /path/music:/music spotdl-webui:local
```

### Проверить и убрать старый автосинк

1. Открой UI, войди по токену.
2. `docker logs spotdl-webui` — через ~`AUTOSYNC_START_DELAY` сек стартует
   «Автосинхронизация (по расписанию)».
3. Убедившись, что всё работает — **удали старый стек автосинка** в Portainer
   (теперь синк по расписанию делает этот сервис). См. раздел «Замена старого
   контейнера-автосинка».

### Тома и порт (заданы в compose, проверьте под свой сервер)

| Хост | Контейнер | Назначение |
|------|-----------|-----------|
| `/srv/dev-disk-by-uuid-6c40d758-…/data/spotdl` | `/conf` | playlists.txt, cookies.txt, *.spotdl, errors/ |
| `/srv/dev-disk-by-uuid-be7624de-…/storage/music` | `/music` | библиотека `spotify/`, плейлисты `playlists/` |

Порт: **4535 → 8000** (4533 занят Navidrome, 4534 — Syncify).

## Переменные окружения

| Переменная | По умолчанию | Описание |
|-----------|--------------|----------|
| `APP_AUTH_TOKEN` | — (обязательна) | Токен доступа к UI. Без него сервис не стартует. |
| `PUID` | `998` | UID процесса (тот же, под которым Navidrome читает музыку). |
| `PGID` | `100` | GID процесса. |
| `WEB_PORT` | `8000` | Внутренний порт uvicorn. |
| `CONF_DIR` | `/conf` | Корень данных spotdl. |
| `MUSIC_DIR` | `/music` | Корень музыки. |
| `OUTPUT_TEMPLATE` | `…/{album-artist}/{album}/{track-number} - {title}.{output-ext}` | Шаблон вывода spotdl (должен совпадать с автосинком). |
| `AUDIO_FORMAT` | `mp3` | Формат загрузки. |
| `UPLOAD_BITRATE` | `320k` | Битрейт конвертации (заливка, Deezer, Spotify-апгрейд). 320k — максимум Spotify. `auto` — не форсировать. |
| `DEEZER_ARL` | — | ARL-токен Deezer для фолбэка. Альтернатива — файл `/conf/deezer_arl.txt`. Без него кнопка Deezer вернёт 400. |
| `ZOTIFY_CREDENTIALS_FILE` | `/conf/zotify_credentials.json` | Путь к credentials.json Zotify (создаётся при первом логине). |
| `ZOTIFY_USERNAME` / `ZOTIFY_PASSWORD` | — | Альтернатива credentials.json — логин/пароль Spotify (хуже, секрет в конфиге). |
| `ZOTIFY_QUALITY` | `very_high` | `very_high`=320k (нужен Premium), `high`=160k, `normal`=96k, `auto`=макс. для аккаунта. |
| `ZOTIFY_SAFE_MODE` | `true` | Безопасный режим: одиночные «Spotify 320k» качать в **real-time** (скорость прослушивания, анти-бан). Массовая закачка и апгрейд — всегда real-time; при включённом режиме у массовой ещё пауза между треками. Тумблер в UI. |
| `ZOTIFY_BULK_WAIT_MIN` / `ZOTIFY_BULK_WAIT_MAX` | `5` / `15` | Idle-пауза (сек) между треками поверх real-time. Апгрейд — всегда; массовая «Скачать все» — при безопасном режиме. `MAX=0` — без паузы. |
| `UPGRADE_MIN_BITRATE` | `300` | Апгрейд пропускает файлы, у которых битрейт уже ≥ этого (kbps), даже без метки. |
| `UPGRADE_PER_DAY` | `0` | Лимит апгрейд-загрузок в сутки (анти-бан). `0` = без лимита (только паузы). |
| `AUTOSYNC_INTERVAL_HOURS` | `24` | Период фонового автосинка (sync всех плейлистов). `0` — выключить планировщик. |
| `AUTOSYNC_ON_START` | `true` | Запускать один автосинк вскоре после старта контейнера. |
| `AUTOSYNC_START_DELAY` | `20` | Задержка (сек) перед первым автосинком после старта. |

Файлы создаются с `umask 002` под `PUID:PGID`, поэтому Navidrome (та же группа)
их читает. Сервис чаунит только свой `HOME` и папку локов — **общую музыку и
чужие данные автосинка он не трогает**.

## Замена старого контейнера-автосинка

В этот сервис встроен **фоновый планировщик** (поток внутри контейнера): раз в
`AUTOSYNC_INTERVAL_HOURS` он сам прогоняет `sync` по всем плейлистам — ровно та же
работа, что делал отдельный контейнер с `while true; … sleep 86400`. Поэтому
старый контейнер-автосинк можно удалить — всё (и автоматический синк по
расписанию, и веб-морда, и ручное добивание) делает один этот сервис.

Порядок миграции:
1. Подними этот стек, убедись что UI открывается и `docker logs` показывает
   `Автосинхронизация (по расписанию)` примерно через `AUTOSYNC_START_DELAY` сек
   после старта (или запусти «Синхронизировать всё» вручную).
2. Останови и удали старый стек автосинка в Portainer.
3. Готово — остаётся один контейнер. Автосинк продолжает идти по расписанию,
   просто теперь изнутри веб-сервиса.

> Автосинк использует тот же воркер и те же файловые локи, что и ручные операции,
> поэтому фоновый прогон и ручное добивание не подерутся за один плейлист.
> Не запускай старый и новый автосинк **одновременно** на длительное время —
> смысла нет, и они будут делать двойную работу (хотя локи защитят от гонки за
> один `.spotdl`/`.m3u8`).

## Deezer (фолбэк для треков, которых нет на YouTube)

spotdl берёт аудио с YouTube, но там пользовательский каталог — редкие треки
отсутствуют. Deezer — лицензированный стриминг с тем же каталогом лейблов, что и
Spotify, поэтому почти любой трек со Spotify есть и на Deezer и матчится **точно
по ISRC**. Кнопка «Deezer» у строки ненайденного трека:
1. берёт ISRC трека со Spotify;
2. находит ту же запись в Deezer, скачивает и расшифровывает;
3. кладёт в библиотеку с метаданными/обложкой со Spotify (как обычная загрузка),
   sync обновляет m3u, трек уходит из «ненайденных».

**Настройка ARL-токена** (это секрет уровня пароля от Deezer-аккаунта):
1. Залогинься в Deezer в браузере → DevTools → Application → Cookies →
   `https://www.deezer.com` → значение cookie **`arl`**.
2. Положи его в файл на сервере (рекомендуется — не светится в конфиге стека):
   ```sh
   echo 'ТВОЙ_ARL' > /srv/.../data/spotdl/deezer_arl.txt
   ```
   Файл монтируется как `/conf/deezer_arl.txt`. Либо задай env `DEEZER_ARL` в стеке.
3. ARL живёт несколько месяцев; при «недействителен» — обнови по той же схеме.

> Бесплатный Deezer-аккаунт отдаёт MP3 128 kbps, Premium/HiFi — 320k/FLAC.
> Скачивание из Deezer — серая зона (нарушает ToS Deezer), используется на свой
> риск для личной библиотеки.

## Spotify напрямую (320k через librespot)

Кнопка «Spotify 320k» качает аудио **прямо со Spotify** через твой аккаунт
(librespot). С Premium — 320 kbps Ogg Vorbis (максимум, что отдаёт Spotify;
lossless он не даёт). Метаданные/обложку/путь даёт spotdl, аудио — librespot
**напрямую по track-id, минуя `api.spotify.com`** (иначе ловится 429 rate limit).
Кнопка «Zotify 320k» у строки качает трек и кладёт в библиотеку как обычная
загрузка. Находит **всё, что есть в Spotify** — идеальный фолбэк для отсутствующих
на YouTube.

**Авторизация — через OAuth** (нужен Spotify-аккаунт, для 320k — Premium).
Подходит и для аккаунтов через Facebook/Google/Apple (у них нет пароля Spotify,
а username/password Spotify для сторонних клиентов всё равно заблокировал).
Генерируем переиспользуемый `credentials.json` один раз, прямо на сервере:

```sh
docker exec -it spotdl-webui python -m app.gen_zotify_creds /conf/zotify_credentials.json
```

1. Скрипт печатает ссылку — открой её в браузере на ПК и войди в Spotify
   (кнопка «Continue with Facebook» там есть).
2. Браузер откроет `http://127.0.0.1:5588/login?code=...` — страница НЕ загрузится,
   это нормально. Скопируй значение после `code=` (или весь URL) и вставь в терминал.
3. Скрипт сохранит `/conf/zotify_credentials.json` — дальше Zotify работает сам.

> Вариант `ZOTIFY_USERNAME`/`ZOTIFY_PASSWORD` оставлен для аккаунтов с паролем, но
> для Facebook-входа он не сработает — используй OAuth-генератор выше.

**Риск и осторожность:**
- Использование librespot нарушает ToS Spotify; **аккаунт могут забанить**,
  особенно при массовом скачивании. Используется на свой риск.
- Снижает риск: **безопасный режим** (паузы между загрузками, тумблер в UI) и
  лимит `UPGRADE_PER_DAY`. Для разовых треков риск минимальный.
- Совет: рассмотри отдельный аккаунт; на free-аккаунте качество только 160k.

> Это Step 1 (ручная кнопка). Фоновый массовый «апгрейд качества» (медленная
> замена YouTube-треков на 320k неделями, с прогрессом в UI) — следующий шаг,
> после подтверждения, что авторизация и скачивание работают на сервере.

## Cookies для YouTube

Без cookies YouTube на объёме начинает требовать «Sign in to confirm you're not a
bot». Положите файл cookies (формат Netscape) по пути:

```
<data/spotdl на хосте>/cookies.txt   →   внутри контейнера /conf/cookies.txt
```

Экспортировать можно расширением браузера (напр. «Get cookies.txt»). Сервис
передаёт его в spotdl через `--cookie-file /conf/cookies.txt`.

## Как пользоваться

1. Откройте `http://<сервер>:4535`, введите токен.
2. **Ненайденные** — основная вкладка. Для трека, который не нашёлся:
   - нажмите «искать на YT», найдите подходящее видео/трек;
   - вставьте его URL в поле «Источник YouTube» (можно заполнить сразу много);
   - нажмите **«Скачать»** у строки (по ссылке из поля), либо **«Скачать все»** —
     у этой кнопки сверху dropdown «Источник»: из поля URL / Deezer / Spotify 320k.
   - процесс **не блокирует**: справа снизу появится панель «Задачи» со статусами
     (в очереди / качается / готово / ошибка), клик по задаче открывает её лог.
     Полные логи дублируются в `docker logs`.
   - скачанный трек **сразу дописывается** в `<safe>.m3u8` (без полного скана
     плейлиста), а успешная строка исчезает из списка. Строки с ошибкой остаются
     и подсвечиваются — смотрите их лог.
   - **если трека нет на YouTube** — жми **«Spotify 320k»** (лучшее качество, прямо
     со Spotify; нужны креды, см. «Spotify напрямую») или **«Deezer»** (по ISRC,
     нужен ARL). Оба качают автоматически, ничего вставлять не надо.
   - либо, если скачал файл сторонним способом — жми **«📁 Файл»** и выбери его:
     сервис даст ему метаданные и обложку со Spotify и положит в библиотеку.
3. **Плейлисты** — добавляйте записи (`Имя|ссылка`), запускайте sync.
4. Navidrome подхватит изменения сам (скан раз в час + watch).

## Чек-лист после деплоя на сервере

Полную проверку (Navidrome, права `998:100`, cookies, реальные загрузки) можно
сделать только на сервере. Пройдите по пунктам:

1. **Инструменты внутри контейнера:**
   ```sh
   docker exec spotdl-webui spotdl --version     # ожидается версия (напр. 4.5.0)
   docker exec spotdl-webui deno --version        # deno найден
   docker exec spotdl-webui ffmpeg -version | head -1
   ```
2. **Быстрый старт без установки в рантайме:** `docker logs spotdl-webui` — не
   должно быть apt/pip-install при старте; сразу строка `[entrypoint] запуск под
   998:100 …` и старт uvicorn.
3. **UI и токен:** откройте `http://<сервер>:4535` — должен запросить токен;
   неверный токен не пускает, верный — открывает интерфейс.
4. **Плейлисты:** вкладка «Плейлисты» показывает записи из `playlists.txt`.
   Добавьте тестовую запись → проверьте, что в файле появилась строка
   `Имя|ссылка`; удалите → строка исчезла, комментарии (`#…`) на месте.
5. **safe-имя:** для записи с `:`/кириллицей/японским (напр. `NieR: Automata OST`)
   sync создаёт `/music/playlists/NieR Automata OST.m3u8` и папки в
   `/music/spotify/…` — без «битых» символов.
6. **Ненайденные:** вкладка показывает треки из `errors/*.txt`, сгруппированы по
   плейлисту, видны Spotify-URL и `Artist - Title`.
7. **Поток добивания (ключевой):** вставьте YouTube-URL → «Найти и добить» →
   в логе: download → sync → удаление из errors. После завершения:
   - файл появился в `/music/spotify/<album-artist>/<album>/…mp3`;
   - трек присутствует в `/music/playlists/<safe>.m3u8`;
   - строка ушла из списка ненайденных;
   - Navidrome показал трек в плейлисте (после скана/watch).
8. **Права:** `ls -ln /music/spotify/...` — владелец `998:100`, файлы читаемы
   группой. Права на общей папке музыки не изменились у чужих файлов.
9. **Лок / отсутствие гонки с автосинком:** запустите sync плейлиста в UI и
   убедитесь, что появляется `/conf/.webui-locks/<id>.lock` на время операции и
   исчезает после; одновременный ручной sync того же плейлиста ждёт.
10. **Логи:** лог запущенной задачи виден в UI в реальном времени.
11. **Фоновый автосинк:** через `AUTOSYNC_START_DELAY` сек после старта во вкладке
    «Задачи» появляется задача «Автосинхронизация (по расписанию)». Если её нет —
    проверьте `AUTOSYNC_INTERVAL_HOURS` (не `0`) в логах: `docker logs spotdl-webui`.

## Troubleshooting (известные грабли)

- **Дубли треков в списке ненайденных после повторных сканов.** spotdl пишет
  `--save-errors` в режиме дозаписи (`"a"`), поэтому каждый sync добавляет блок
  «таймстамп + ненайденные» в конец файла. Решено двумя слоями: парсер
  дедуплицирует треки по Spotify-URL (дубли не видны даже в уже «грязных»
  файлах), а перед каждым sync errors-файл плейлиста сбрасывается, чтобы spotdl
  записал свежий полный список без накопления и без устаревших записей уже
  добитых треков.

- **`OSError: libresolv.so.2 not found` на старте spotdl.** Это про образ
  `spotdl/spotify-downloader:latest` — его зависимость `tls_client` требует
  `libresolv`, которой нет в его базовой ОС. Решение уже заложено: база —
  `python:3.12-slim-bookworm`, где `libresolv.so.2` присутствует.
- **`AudioProviderError` / «Some YouTube downloads require Deno».** spotdl не
  видит Deno под runtime-пользователем (998). Частая причина: Deno лежал
  **симлинком** в `/root/.config/spotdl/deno`, а в `/root` пользователю 998 хода
  нет (mode 700) — для spotdl это «deno отсутствует». Решение уже в коде:
  `Dockerfile` кладёт **реальный** бинарь `deno` в `/usr/local/bin/deno`
  (mode 755), а `entrypoint.sh` при старте заменяет симлинк реальной копией на
  случай старого образа. Проверка: `docker exec -u 998 spotdl-webui deno --version`.
- **`PermissionError: '/app/music...'` / m3u пишется не туда.** Баг spotdl 4.5.0:
  части пути `--m3u` прогоняются через sanitize, который вырезает `/`, и
  абсолютный путь становится относительным от текущей папки. Решение в коде:
  spotdl запускается с **cwd=`/`** (так же, как контейнер автосинка), поэтому
  путь резолвится обратно в `/music/...`.
- **`PermissionError` при записи в `/music/spotify/...` (новые треки).** Папки
  библиотеки, созданные старым автосинком под `root`, могут быть не доступны на
  запись пользователю `998`. Сделайте дерево музыки доступным группе (на хосте,
  один раз):
  ```sh
  chown -R 998:100 /srv/.../storage/music/spotify /srv/.../storage/music/playlists
  chmod -R g+rwX   /srv/.../storage/music/spotify /srv/.../storage/music/playlists
  ```
  (существующие файлы остаются читаемыми; новым трекам нужна запись в эти папки).
- **Трек исчез из «Ненайденных», но в библиотеке/Navidrome его нет.** Так было до
  фикса: spotdl мог завершиться с кодом 0 даже при провале загрузки. Теперь
  сервис определяет провал по выводу (`AudioProviderError`, `LookupError` и т.п.)
  и **не убирает трек из списка**, пока он реально не скачался. Если видите трек
  в статусе «ошибка» — откройте его лог в панели «Задачи» (обычно это Deno или
  права на запись выше).
- **YouTube: «Sign in to confirm you're not a bot».** Нет/протухли cookies.
  Обновите `/conf/cookies.txt`.
- **Файлы не видны Navidrome / «permission denied».** Проверьте `PUID/PGID`
  (`998:100`) и что папка музыки записываема этой группой. Сервис пишет с
  `umask 002`.
- **Трек скачался, но не появился в плейлисте Navidrome.** Navidrome резолвит
  пути m3u относительно расположения m3u-файла (или абсолютные). m3u пишет сам
  `spotdl sync` — не редактируйте его руками. Если sync не подхватил готовый
  файл, проверьте, что `OUTPUT_TEMPLATE` совпадает с автосинком (иначе путь
  файла не совпадёт с тем, что ждёт sync).
- **«Плейлист занят, ждём освобождения».** Файловый лок: идёт sync этого
  плейлиста (нашим сервисом). Протухшие локи (старше 30 мин) снимаются
  автоматически.
- **Контейнер не стартует.** Скорее всего не задан `APP_AUTH_TOKEN` — задайте.

## Разработка / тесты

```sh
# тесты соответствия safe-имени, id и парсинга errors (без сети)
python tests/test_naming.py
# или
python -m pytest tests/ -q

# локальный запуск (нужны fastapi/uvicorn и spotdl в PATH)
CONF_DIR=./_data/conf MUSIC_DIR=./_data/music APP_AUTH_TOKEN=dev \
  uvicorn app.main:app --reload --port 8000
```

### Структура

```
app/
  main.py          FastAPI: маршруты, аутентификация
  config.py        пути/шаблоны из окружения
  naming.py        safe-имя, md5-id, тип URL (тесты!)
  playlists.py     чтение/запись playlists.txt
  errors_parser.py разбор errors/*.txt, удаление добитых треков
  health.py        проверка окружения (cookies, права записи, deno) для баннера
  library.py       общая логика: путь по шаблону + ffmpeg + мета/обложка Spotify
  place_localfile.py  заливка локального файла (исп. library)
  deezer.py        скачивание+расшифровка трека с Deezer (requests+pycryptodome)
  deezer_dl.py     Deezer-фолбэк по ISRC (исп. deezer + library)
  spotify_dl.py    скачивание напрямую со Spotify (librespot, 320k, без api.spotify.com)
  gen_zotify_creds.py  одноразовая генерация credentials.json через OAuth (FB-вход)
  settings.py      рантайм-настройки (безопасный режим) в /conf, тумблер в UI
  upgrade.py       Step 2: фоновый массовый апгрейд библиотеки до 320k с метками
  jobs.py          две дорожки очереди, воркеры, лок, запуск spotdl, планировщик
  static/          index.html, app.js, style.css (тёмная SPA)
Dockerfile                    самодостаточный образ (ffmpeg+spotdl+deno+app)
docker-compose.yml            стек для Portainer (образ из GHCR)
entrypoint.sh                 PUID/PGID, umask, deno, дроп привилегий
.github/workflows/build.yml   CI: сборка и публикация образа в GHCR
```
